# Localisation status

Generated by `pnpm tsx scripts/i18n-inventory.ts --write` (a heuristic scan with the TypeScript parser; see the
script's header for what it counts). Re-run it after adding interface text. `tests/unit/i18n-coverage.test.ts`
fails when a strings file registered in `src/lib/i18n/registry.ts` lacks an Arabic or Urdu string, and
`tests/e2e/i18n.spec.ts` when a route renders English interface words in /ar or /ur outside English-marked content.

**All Arabic and Urdu interface strings are drafts that need review by a qualified translator** (the footer says so:
`draftArabicUi`, `draftUrduUi`). Religious content (Quran, hadith, scholarly statements, editorial pages, database
rows) is not interface text and is not translated here: in the Arabic and Urdu interfaces it is shown as it is and
marked `lang="en" dir="ltr"` (`englishContent()` in `src/lib/i18n/locales.ts`). The few interface sentences that
state a religious fact (the Nuh note in Life Through the Ages, the Last Hour lead, the qira'at distinction points) are
deliberately left English in Urdu (and where noted in Arabic) for a qualified translator and the scholarly reviewers.

UI strings = leaves of the module's strings files + English strings still hard-coded in its files. EN = the share that
comes from a strings file (everything renders in English either way); AR and UR = the share that renders in that
language (a leaf identical to English with Latin words does not count).
